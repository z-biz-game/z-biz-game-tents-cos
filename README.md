# 帐篷 · Tents（零猜测树与帐篷推理）

> *边上的数字不告诉你哪一格有帐篷，只告诉你这一行里有几顶。出货的每一局都被那五条计数规则从空盘推到底过一次；
> 同一块盘另由第二套互不信任的穷举计数器判定唯一、并和铅笔的结果**逐格**比对（`tools/scenarios.js:293-294`），
> 提示的每一句还要再对着盘面复述一遍（`提示没有一句与盘面不符`）——**可靠是证明了的，完备不是承诺**。*

浏览器原生的 **Tents / 帐篷**：无构建步骤、无打包器、**零美术与音频文件**——
树、帐篷、草地、行列数字全部由 canvas 现画，音效由 WebAudio 合成，页面里只有**一个
`<script type="module">`**，界面只有**一个 `<canvas>`** 加一栏读数。

玩法是**在树旁扎帐篷**：树已经种在盘上，帐篷只能放在某棵树上下左右四格里；
两顶帐篷**八格之内不许互碰（斜角也算）**；行和列边的数字写着这一行、这一列各有几顶帐篷，
没有数字的边不作限制；除树以外的每一格最后都必须落下记号——帐篷，或者确认过的草地。

- **核心承诺 1｜零猜测**：出货的每一局都能 **只用下面那五条规则从空盘推到底**。这不是文案，是准入门槛——
  `pruneClues()` 每删一个数字都要重跑一遍铅笔路径，删完推不到底就回滚。
  实测：5 档 × 40 局全部出货，"推不出来的盘 0"；`engine-test` 里那条断言叫
  **`出货的盘全都能纯计数推完`**（60 局抽盘，闸门单独钉，见 DESIGN §4）。
- **核心承诺 2｜唯一解**：`countSolutions()` 是一台**不含任何推理规则**的逐格穷举计数器，
  它只从 `tents.js` 借四个常量，树、营位、八邻、行列归属四张表全部按题意**重新推了一遍**。
  铅笔路径说"这一盘只有一个答案"时，它必须数出 1，而且要**逐格**给出同一份帐篷，否则不出货
  （实测 **16/16 局**穷举复核与铅笔判定一致）。
- **核心承诺 3｜提示不是答案**：提示走的是**同一个** `solve()` 产出的推导脚本，所以它必须点名
  用了哪条规则、落在哪一格（`第4行 写着 2，还差 1 顶，而它只剩 1 格可放——那 1 格都必须扎营`）。
  脚本只由数字生成、**不读玩家的墨水**，所以墨水已经和数字顶上了的时候，提示**拒绝落子也不收费**，
  只说"这里必须是帐篷"。
- **核心承诺 4｜矛盾会被提前说出来**：多放一顶帐篷往往**不违反任何一个数字**——行列还数得过来。
  `reachable()` 把玩家的记号当成前提跑一遍规则，一旦逼出矛盾，状态行立刻说
  "这些帐篷和数字已经矛盾了：不管剩下的格怎么放，都不可能让每棵树有帐、每个数字对上"（见 DESIGN §6）。
- **诚实的边界｜规则只保证可靠，不保证推得完**：在 358 块样本盘上（三个来源：满数字、生成器的闸门剪过的、
  以及**完全不加闸门**随手抹掉 45% 数字的），铅笔写下 **11,561 格**，**没有一格和穷举数出的任何一个解相冲**——
  这才是"提示只说推得出的那一步"的字面意思，而且是**逐格**对着**全部**解断言的。
  可同一批样本里，265 块唯一解的盘仍有 **6 块**让铅笔停在半路：**Tents 可以被唯一确定，却不被"数数"决定**。
  所以本作的规则集是**除可靠之外什么都不承诺**的，那个缺口不由更聪明的求解器补，由出题器的闸门补
  （见 DESIGN §4）。
- 难度不是标签：`初学 → 大师` 五档的分数带是**实测**出来的（`npm run balance` 打印分位表），
  档位排的是「盘面多大 × 帐篷多密 × 多下了几棵闲树 × 留下多少数字」，`band` 是**选取目标**，
  `balance` 盯着不许漂移（见 DESIGN §8）。
- 规模：9 个 ES Module / 2,186 行 JS + 5 个验证脚本 / 2,361 行 + 521 行 CSS/HTML，**运行时依赖 0 个**。
- 验证：**148 项 Node 断言全绿**（`node tools/engine-test.mjs` → `148 通过 / 0 失败`）+ **9 个浏览器场景
  / 516 项断言**（engine 44 / gen 110 / play 80 / hint 30 / stroke 39 / conflict 48 / save 60 /
  resume 40 / layout 65——场景名写进 `tools/verify.sh` 的默认清单，纪律是读 DOM 几何与画布像素、
  不读标志位；真实输出贴在下面）。
- **在线试玩**：<https://z-biz-game.github.io/z-biz-game-tents-cos/>（`main` 分支推送即自动部署；
  Pages 的产物就是 `index.html` + `css/` + `js/` 三项**文件拷贝**，服务器、桌面壳、验证脚本
  和这两份文档都不进 artifact——没有打包器，也就没有"构建产物和源码不一致"这件事）

## 玩法

| 操作 | 行为 |
|---|---|
| **拖动** | 沿路给经过的格铺上当前这笔的记号；一笔算一步，重复经过的格只算一次 |
| **再点自己已经放过的格** | 擦掉——同记号再点就是橡皮，一笔什么都没改就整笔作废 |
| **`T` / `G`**（或 `M` 切换） | 选这一笔放**帐篷**还是确认**草地** |
| **提示**（或 `H`） | 给出数字当前推得出的那一格，并点名规则；这一步真的落子，也真的计入求助次数 |
| **撤销**（或 `Z`） | 退掉一整个手势——一笔铺过的格子一起回来；提示退掉**不算**没求助过 |

判胜用的是 `verify()`：只读盘面，逐条检查"没有空格、每顶帐篷旁有树、帐篷互不接触、
每个数字数得对、每棵树旁有帐"。它不读推导脚本，也不读铅笔留在内存里的状态，
所以**提示逻辑写错也伪造不出一场胜利**。

## 五条规则（提示只会说这些）

| 规则 | 说什么 | 权重 |
|---|---|---|
| 无树不扎营 | 四边没有树的格子，帐篷无处可配，只能是草地 | 1 |
| 一帐八周空 | 这里有一顶帐篷，它八格之内（斜角也算）都不许再有 | 1 |
| 行列封顶 | 数字已经凑满，这一行剩下的格子都得留成草地 | 1 |
| 只差这些 | 还差 k 顶而只剩 k 格可放 → 那 k 格都必须扎营 | 1.5 |
| 树唯一落点 | 这棵树旁只剩一格还能扎营，帐篷只能在这里 | 1 |

五条都只数**一行（一列）自己的账**或**一棵树自己的账**，所以每一条写下的格子在该盘面的
**每一个解**里都成立。这就是"提示不会骗人"得以成立的原因，也是 11,561 格 0 处反例的由来。

## 难度是量出来的

`npm run balance`（SAMPLES=40，2026-09-27）：

| 档 | 盘面 | 密度（帐篷 / 闲树） | 留多少数字 | 留下的数字（实测中位） | 分数带（选取目标） | 实测中位 | 命中区间 | 平均抽几次 | 出题耗时 |
|---|---|---|---|---|---|---|---|---|---|
| 初学 | 5×5 | 0.26 / 0.20 | 100% | 10/10 | 15–21 | 20.5 | 40/40 | 2.8 | 0.4 ms |
| 上手 | 6×6 | 0.25 / 0.25 | 84% | 10/12 | 23–29 | 28.0 | 40/40 | 3.9 | 1.1 ms |
| 熟练 | 7×7 | 0.24 / 0.30 | 72% | 10/14 | 32–38 | 37.0 | 40/40 | 5.3 | 1.3 ms |
| 高阶 | 8×8 | 0.23 / 0.35 | 56% | 9/16 | 41–48 | 47.0 | 40/40 | 5.8 | 2.3 ms |
| 大师 | 9×9 | 0.22 / 0.40 | 44% | 8/18 | 52–61 | 59.0 | 40/40 | 4.0 | 2.2 ms |

五档的出题成功率都是 40/40，"推不出来的盘"都是 0。耗时那一列是**同一台空载机器上一次运行**的实测值
（最慢的一档 2.3 ms/局；同一份代码另一次跑是 2.1），换台机器、并跑别的东西时它会跟着漂——所以选盘条件里
**不许**掺进墙钟时间：一次偶然的慢求解若改变了抽中哪块盘，"续局重绘出同一块盘"就会红（见 DESIGN §8）。

分数是**推理步数的加权和**（每条规则按上表的权重计）：实测每一档出货盘的步数都**恒等于能下墨的格子数**，
于是分数 = 格子数 + 0.5 ×（"只差这些"用了几次，最多测到 7 次）——也就是说**分数轴基本被盘面大小买断了**。
让高阶和大师**难**而不是**大**的，只有剪数字这一件事：8×8 的 16 条边里高阶只留 9 条（56%），
9×9 的 18 条边里大师只留 8 条（44%），缺的那些格子得靠别的线和别的树推出来
（见 DESIGN §8 的度量诚实）。
`balance` 会拒绝不再单调的阶梯，也会拒绝命中率掉到个位数的档。

## 目录

```
index.html          一个 canvas + 侧栏读数
css/game.css        全部颜色来自 theme.js 注入的 CSS 变量
js/engine/tents.js  模型、五条规则、铅笔路径、独立 verify/reachable/diagnose
js/engine/count.js  独立的逐格穷举计数器（唯一性的第二意见，只 import 四个常量）
js/engine/generate.js 种帐篷 → 配树与闲树 → 按"铅笔仍推得完"删数字 → 按难度带抽盘
js/ui/game.js       状态机：手势、撤销、提示、判胜
js/render/board.js  几何 + 绘制 + 命中（布局与绘制共用同一套数）

tools/              engine-test / balance / playtest(CDP) / scenarios / verify.sh
```
